### Layout and inventory qualifications

Copy the centered 800px editor, 12px horizontal/28px vertical padding, 24px section gaps, 10px card radii and sticky action bar (S §§8.1,19.2). Keep Devin's section order. List uses Name / Last 30 days / Last triggered, not Cursor's table. Gallery uses existing rounded cards and 2/3-column grid. Event charts are 166px high; issue sheet is 560px (S §§6.4,7.3,18).

The full captured inventory also includes Preflight enable/disclosure, runtime/environment/snapshot, timeout, script modal, secrets picker, contract text, clear persistent state confirmation, conflict handling, code-only save, and run/log modal (S §13.5, Appendix I §11). Those are **not implemented in the listed clean feature files**. The same applies to the complete scratchpad file browser/editor and original rich mention editor. `ScratchpadRow` exposes a callback, but the page does not supply it. Recover captured components before claiming these controls work. Appendix A retains their captured copy and call sites.

`ErrorLogsPage` is expressly reconstructed: its 50-row/90-day query, 960px frame and session precedence are not verified original behavior. Only its route and catalog copy are established. Quarantine it from exact-copy approval until the org-scoped original is captured; do not promote its chosen constants into the contract.

Other donor differences matter: local `model/sources.tsx` is a partial static schema registry, whereas captured schemas are dynamic; the editor's singleton set includes schedule/code scan, whereas the captured singleton is only incoming webhook; `model/rrule.ts` is a minimal parser that drops unsupported properties and interprets DTSTART using local time; the original validates timezone conversion. The local data store is mock transport, not the production API. See S Appendix I §§12–14 and Appendix A; these are repair requirements, not new product features.

Template filtering hides explicitly disconnected required integrations and unsupported triggers. Missing MCPs reduce readiness ordering; they do not hide templates. Stable ordering is unused, then ready, then server order. Search requires every token somewhere in combined searchable metadata. No catalog list can establish current server templates (S §§7.1–7.2).
